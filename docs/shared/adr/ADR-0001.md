# ADR-0001 - Initial Rewrite Stack and Dependency Constraints

- ADR ID: ADR-0001
- Title: Lightweight cross-platform stack with bundled runtime tooling
- Status: Accepted
- Date: 2026-03-03
- Authors: LANLauncherNG maintainers
- Related Tickets: T-001, T-002, T-003

## Context
LANLauncherNG must run on Windows and Linux with minimal user setup and no dependency-heavy runtime requirements. The legacy implementation is Windows-bound and tightly coupled to bundled executables and UI script bridges.

## Decision
- Backend: single-binary architecture (Go preferred baseline).
- Frontend: lightweight web UI with explicit i18n layer and static build output.
- Storage: SQLite.
- Sync: provider abstraction with initial Resilio-compatible provider.
- Packaging: include required runtime binaries in `vendor/bin/<platform>` with checksums and licenses.
- Dependency control: avoid heavy frameworks by default; any major dependency needs a dedicated ADR.

## Options Considered
- Option A: Electron desktop app + Node backend.
- Option B: Single-binary backend + lightweight web frontend.
- Option C: Keep native Windows-centric launcher and port incrementally.

## Rationale
Option B provides the best balance of cross-platform compatibility, low runtime overhead, and maintainability while keeping packaging practical for offline LAN environments.

## Consequences
### Positive
- Smaller runtime footprint.
- Easier cross-platform delivery.
- Cleaner separation between UI and system operations.

### Negative
- Requires explicit packaging discipline for bundled tools.
- Requires stronger API contract between frontend and backend.

### Follow-up
- Introduce dependency review checklist in PR process.
- Add startup integrity checks for bundled binaries.

## Rollout Plan
1. Establish module boundaries in `src/core` and `src/frontend`.
2. Implement provider interfaces and platform adapters.
3. Add packaging and checksum validation scripts.

## Validation
- Backend starts on Windows and Linux without external runtime installs.
- Frontend consumes backend API successfully on both OS targets.
- Packaged builds run offline with bundled tools.
